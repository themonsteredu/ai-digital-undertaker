# 디지털 장의사 · MOAKIT

초등 고학년·중학생의 개인정보 보호 진로 체험. 2차시 80분 중 웹 활동 약 45분을 위한 구성입니다.

## 수업 시작

첫 화면 오른쪽 아래 설정 → 교사용 비밀번호 3035 → 수업 만들기 → 난이도 선택 → 네 자리 코드 안내.
학생은 코드와 별명으로 입장합니다. 처음 참여 시 중복 별명에 숫자가 붙습니다. 다른 기기에서는 `이어서 하기`와 발급된 별명을 정확하게 입력합니다.

## 구성

- 사건 1: 송장·영수증 조사, 세 가지 처리 판단, 보고서
- 사건 2: 사진 단서, 삭제 요청, 공개·위치·태그 설정, 중등 토론
- 사건 3: 검색 결과 구분, 계정별 처리, 가상 계정 8개 정리
- 사건 4: 단톡방 개인정보, 의심 링크, 피해 기록과 어른 도움
- 마무리: 반 평균 비교(점수·등수 없음), 약속 카드, 가림 도장 설계
- 교사: 학생 현황, 집계, 놓친 항목, 선택 분포, 카드 벽, 도장 갤러리·학생 투표, 슬라이드 10장

## 도장

기본 40×15mm, 여백 1mm. 기계 규격이 제공되지 않아 가로 15~80mm, 세로 10~50mm, 여백 0~5mm로 조절합니다. SVG의 물리적 mm 크기와 인쇄 창의 CSS mm 크기로 출력합니다. 삽입되는 흑백 이미지 해상도는 600dpi 기준입니다. 실제 크기 100%로 인쇄하고 기계별 반전·재료 요건은 별도로 확인하세요.
`모의 가림률`은 화면 예시 글씨의 픽셀과 검은 무늬가 겹친 비율이며, 실제 개인정보 제거 성능·OCR 불가율이 아닙니다. 잉크·종이·압력·바코드별로 결과가 달라집니다.

## 데이터와 권한

Supabase `monster-moakit`의 전용 `du_*` 테이블을 사용합니다. 기존 MOAKIT 테이블은 변경하지 않았습니다. 데이터 구조는 `supabase/schema.sql`, 서버는 `supabase/functions/digital-undertaker/index.ts`에 있습니다.

- 모든 전용 테이블에 RLS 활성화, anon/authenticated 직접 테이블 권한 회수
- JWT 확인을 켠 Edge Function을 통하며, 별도 해시 세션으로 학생·교사 권한 분리
- 학생은 자기 기록 수정과 같은 반의 집계·도장 갤러리만 열람
- 교사용 공통 비밀번호는 서버에서만 검사. 교사 세션은 해당 앱의 교사 기능 전체에 접근
- CORS는 배포 앱 주소와 개발 검수 주소만 허용
- 학생 로그인은 요청서에 맞춘 코드+별명 방식. 개인 비밀번호가 없으므로 같은 코드와 별명을 아는 사람이 이어서 들어갈 수 있는 수업용 구조
- 교사 보드는 3초 주기 서버 재조회, 학생 마무리 갤러리는 5초 주기. Supabase WebSocket Realtime 채널을 사용하지 않음
- 수업 삭제는 코드 재입력 후 관련 학생·답·카드·투표·학생 세션을 cascade 삭제
- AI API 호출 없음. 사례·선택 피드백은 검토한 고정 콘텐츠

서버 간 요청만 중계하므로 Vercel의 새 도메인에서도 기존 인증 경계를 유지합니다.

## 개발과 검증

Node 22, pnpm. `pnpm dev`, `pnpm build`, `pnpm start`. Vercel에서는 Next.js 프레임워크로 빌드합니다.
학생의 요청은 같은 도메인의 `/api/activity`를 거쳐 Supabase로 전달됩니다. 서버의 세션·역할 검사를 그대로 유지하며, 배포 주소를 바꿔도 별도의 브라우저 CORS 설정이 필요하지 않습니다.
`node tests/server-smoke.mjs`는 서버에 `QA_DELETE_ME` 수업을 만든 후 삭제하는 통합 검증입니다.
`/qa`는 개발 환경에만 표시되는 가상 데이터 화면 검수 도구입니다. 서버에 연결하거나 인증을 우회하지 않습니다. 프로덕션에서는 사용할 수 없습니다.

## 2026-09-22 수업 화면 개선

송장과 영수증은 가상 개인정보를 사용한 인쇄 양식으로 재현했습니다. 사진·인쇄물 조사는 미리 정해진 클릭 버튼 없이 학생이 직접 드래그해 표시하고 확인합니다. 표시 좌표와 확인 여부는 답안에 저장되어 이어서 활동할 수 있습니다. 영수증은 초등과 중등 모두 조사합니다.
교사용 슬라이드 10장에 학생용 설명·핵심 내용·질문을 넣고 교사 메모와 80분 진행 흐름을 분리했습니다. 전체화면에서도 본문과 질문이 보입니다.

### 사진 표시와 저장 지연 개선
- 의뢰 사진과 수업 슬라이드는 원본 비율을 유지해 전체가 보입니다.
- 학생 답안은 짧은 연속 변경을 하나로 합쳐 저장하고, 같은 답안을 다시 보내지 않습니다. 화면 이동은 저장 응답을 기다리지 않습니다.
- 미전송 답안·진행 위치는 학생별로 현재 탭에 보관해 새로고침 후 재전송합니다. 오류 시 재시도하며, 나가기는 미전송 기록의 저장 완료를 확인합니다.
- `node --experimental-strip-types --test tests/autosave.test.mjs`: 중복 제거·느린 응답·사건 분리·오류 재시도·미전송 복원·완료 기록 보존 검증. 개발용 `/qa`의 ‘느린 저장 테스트’는 저장 응답을 1.5초 지연합니다.

### 화면 맞춤 조사 자료
- 의뢰 소개와 사진·송장 조사 화면은 화면 높이에 맞춰 배치하며 확인·다음 버튼을 함께 표시합니다.
- 송장·영수증·사진은 원본 비율로 자동 축소하고, 확대 후 화면 맞춤으로 복귀할 수 있습니다.
- 첫 택배 사진에도 조사 화면과 동일한 송장·영수증 문서를 표시합니다.
- 1280×600, 820×720, 390×600/720 화면 및 축소 후 표시 판정을 검수했습니다.

### 실사 스타일 조사 자료
- 명찰·학생증·칠판·간판·번호판·케이크 글씨를 사진에 포함하고 런타임 글씨 덧씌움을 제거했습니다.
- 택배 첫 사진과 송장·영수증 조사 자료를 종이 질감과 조명이 있는 가상 사진으로 교체했습니다. 생일 사진의 장소 정보는 사진 속 초대장에 있습니다.
- 6개 사진은 내장 이미지 생성 도구로 만든 가상 수업 자료이며 실제 학생·거래의 촬영 기록이 아닙니다. 프롬프트와 파일 목록은 `docs/photo-asset-prompts.md`에 기록했습니다.
- WebP로 최적화했고 기존 화면 맞춤·확대·직접 표시 방식을 유지합니다.


### 근거를 연결하는 난이도 개편
- 초등은 자료와 판단 연결, 중등은 근거 자료 + 결론 + 이유를 함께 확인합니다. 중등 SNS·계정 조사에는 추가 추론 질문이 있습니다.
- 택배: 송장·영수증의 중복 정보와 공통 포장 안내를 구분합니다.
- SNS: 세 게시물의 사진·날짜·시간·본문을 비교하고, 장소·생활 패턴을 짐작하는 것과 사실로 확정하는 것을 구분합니다.
- 옛 계정: 비슷한 이름·닉네임의 기록을 의뢰인의 기억과 비교합니다. 불충분한 근거는 확인 보류를 선택합니다.
- 단톡방: 앞뒤 대화에서 허락한 공유 범위와 실제 전달 범위를 비교하고, 선물과 무관한 정보 요구를 판단합니다.
- 정답 위치·총개수와 즉시 해설을 미리 노출하지 않습니다. 선택 후 확인해야 하며, 오답에는 재검토 관점만 안내합니다. 2단계 힌트는 요청할 때만 제공합니다.
- 빈 표시·화면 전체 가리기·무관한 표시로 넘어갈 수 없습니다. 택배는 두 자료 모두 조사합니다. 관련 없는 근거까지 모두 선택해도 통과하지 않습니다.
- 판단을 수정하면 확인 상태를 해제합니다. 저장된 근거·이유·시도·힌트 단계는 학생 보고서와 교사 집계에 연결됩니다. 추가 AI 호출이나 DB 변경은 없습니다.
- 기존 활동의 단계 번호는 유지하고 택배·SNS 연결 질문을 보고서 바로 앞에 넣었습니다. 기존 답안과 완료 기록은 유지합니다.
- `node --experimental-strip-types --test tests/investigation.test.mjs tests/autosave.test.mjs`: 판정과 저장 회귀 검증. `/qa`에서 검수 단계·학년·화면 크기를 고를 수 있습니다.
